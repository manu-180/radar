# 01 — Validación de entorno y cliente de Supabase

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger + Vercel.

Paso **01 de 35**.

**Ya existe:** proyecto Next.js inicializado con las carpetas `lib/`, `supabase/`, `scripts/`, `types/`, `test/` y Vitest configurado (paso 00).

## Tarea
1. **`lib/env.ts`** — un schema de Zod que valida `process.env` y exporta un objeto `env` tipado. Si falta una variable **requerida**, lanzar un error claro que la nombre. Las **opcionales** pueden faltar sin romper.

   **Requeridas:**
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `ANTHROPIC_API_KEY`
   - `WASSENGER_API_KEY`
   - `WASSENGER_WEBHOOK_SECRET` — valida que los webhooks entrantes de Wassenger son legítimos
   - `OWNER_WHATSAPP` — teléfono en formato E.164, ej. `+5491112345678`
   - `CRON_SECRET` — string aleatorio largo; protege las rutas de cron
   - `AUTH_SECRET` — string aleatorio largo; firma la cookie de sesión del dashboard
   - `REDDIT_USER_AGENT`
   - `DASHBOARD_PASSWORD`
   - `APP_URL` — URL base del deploy; en local `http://localhost:3000`. Si no está seteada pero existe `VERCEL_URL`, derivar `https://${VERCEL_URL}`.

   **Opcionales (credenciales de fuentes que requieren setup; si faltan, esa fuente queda inerte):**
   - `FREELANCER_OAUTH_TOKEN` — API de Freelancer.com
   - `DISCORD_BOT_TOKEN` — API de Discord
   - `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` — cliente de Telegram
   - `SCRAPER_API_KEY` — servicio de scraping para Workana (paso 34, opcional)

   Agrupar las `NEXT_PUBLIC_*` en un sub-objeto. El módulo se debe poder importar en server y durante el build sin romper.
2. **`lib/supabase/admin.ts`** — exporta `getAdminClient()`, que devuelve un cliente de `@supabase/supabase-js` creado con `SUPABASE_SERVICE_ROLE_KEY` (bypassa RLS). Poné `import 'server-only'` al inicio.
3. **`.env.example`** — todas las variables (requeridas y opcionales) con valores de ejemplo.
4. **`.env.local`** — las mismas claves con placeholders y un comentario arriba: `# Completar con valores reales antes del paso 03`.
5. Confirmar que `.env.local` está en `.gitignore`.

## Criterio de éxito
- `npm run build` pasa.
- Si se borra una variable requerida de `.env.local`, arrancar la app lanza un error de Zod que nombra la variable faltante.
- Si faltan variables opcionales, la app arranca igual sin error.
- `git status` no lista `.env.local`.
