# 27 — Pipeline de integración continua (CI)

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger + Vercel.

Paso **27 de 35**.

**Ya existe:** la aplicación completa con tests unitarios en `test/` y los scripts de npm `test`, `typecheck`, `verify` (00–26).

Este paso agrega un **pipeline de CI** que verifica el código automáticamente antes de cada deploy.

## Tarea
1. **`.github/workflows/ci.yml`** — un GitHub Action que, en cada `push` y `pull_request`:
   - Hace checkout, instala Node, corre `npm ci`.
   - Corre, en orden: `next lint`, `npm run typecheck`, `npm test`, `npm run build`.
   - Falla el workflow si cualquiera de esos pasos falla.
2. Asegurar que el script `verify` de `package.json` corre esa misma secuencia.
3. Documentar en el README que el CI corre con cada push si el repo está en GitHub.

## Decisiones de diseño (respetalas)
- El CI corre solo **tests unitarios** (`npm test`) y el build. **No** corre `npm run eval` (la evaluación del clasificador, paso 14): esa hace llamadas reales a Claude, cuesta dinero y requiere `ANTHROPIC_API_KEY`.
- El CI no necesita secretos: los tests unitarios no pegan a APIs externas.

## Criterio de éxito
- `.github/workflows/ci.yml` existe y define lint → typecheck → test → build.
- `npm run verify` corre la misma secuencia localmente y pasa.
