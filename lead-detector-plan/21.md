# 21 — Detalle de lead y feedback

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger.

Paso **21 de 35**.

**Ya existe:** dashboard con login, layout y lista de leads (19, 20); esquema con `leads` (columnas `feedback`, `feedback_at`, `llm_cost_usd`) (03).

Este paso construye el **detalle de un lead**, con la respuesta sugerida lista para copiar y los botones de feedback.

## Tarea
1. **`app/(dashboard)/leads/[id]/page.tsx`** — la ruta debe ser exactamente `/leads/[id]` (las notificaciones de WhatsApp del paso 17 enlazan ahí). Muestra:
   - **Contexto completo**: título, body, autor, fuente, fecha, link al post original.
   - **Clasificación de la IA**: score, categoría, `reason`, los términos del pre-filtro que matchearon, y el costo (`llm_cost_usd`).
   - **Mensaje sugerido** con un botón "Copiar" (Client Component mínimo).
   - **Botones de feedback**: "Respondí", "Me interesa", "No relevante".
2. **Server action de feedback** — setea `leads.feedback` y `feedback_at`, y revalida la página.

## Decisiones de diseño
- Server Component para los datos; Client Components solo para lo interactivo.
- El **feedback no es cosmético**: lo consume el clasificador (paso 15) como ejemplos dinámicos para calibrarse. Por eso se guarda con timestamp.

## Criterio de éxito
- `/leads/[id]` muestra el detalle completo del lead.
- El botón "Copiar" copia el mensaje sugerido al portapapeles.
- Marcar feedback persiste en la base y se refleja al recargar.
- `npm run build` pasa.
