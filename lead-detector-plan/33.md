# 33 — Fuente Discord: adaptador

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger + Vercel.

Paso **33 de 35**.

**Ya existe:** `lib/sources/` con la interfaz `SourceAdapter`, el registry y adaptadores de referencia (04, 06–10); `lib/http.ts` (`fetchWithRetry`) y `lib/logger.ts` (02); `DISCORD_BOT_TOKEN` opcional en env y el bot ya creado e invitado a los servidores (01, 32); fila en `sources` con slug `discord` (03).

Este paso implementa el **adaptador de Discord** vía la API REST por polling.

## API a usar (API REST de Discord)
- Mensajes de un canal: `GET https://discord.com/api/v10/channels/<CHANNEL_ID>/messages?after=<MESSAGE_ID>&limit=100`
- Header: `Authorization: Bot <DISCORD_BOT_TOKEN>`
- El bot debe estar en el servidor y tener permiso de lectura sobre el canal (setup del paso 32).

## Tarea
1. **`lib/sources/discord.ts`** — implementar `SourceAdapter` con `slug = 'discord'`:
   - `configSchema`: Zod → `{ channels: { name: string, channelId: string, guildId: string }[] }`.
   - `fetchItems(config, cursor)`:
     - Si falta `DISCORD_BOT_TOKEN`, devolver `{ items: [], cursor }` sin error.
     - El `cursor` guarda `{ [channelId]: lastMessageId }`.
     - Por cada canal, traer los mensajes con `after = lastMessageId` usando `fetchWithRetry` (header `Authorization: Bot ...`).
     - Devolver `{ items, cursor }` con el cursor actualizado por canal.
   - Logueá con `lib/logger.ts`.
2. **Mapeo a `RawItem`**: `externalId` = `discord:<messageId>`; `body` = `content` del mensaje; `title` = primera línea recortada; `url` = `https://discord.com/channels/<guildId>/<channelId>/<messageId>`; `author` = el username del autor; `postedAt` = `timestamp`; `raw` = el mensaje.
3. **Registrar** el adaptador con `registerSource(...)` e importarlo desde `lib/sources/index.ts`.
4. **Activar la fuente**: actualizar la fila `discord` en `sources` → `enabled = true` y `config.channels` con los canales reales (IDs del paso 32).
5. **`scripts/test-discord-adapter.ts`** — script `npx tsx` que ejecuta el adaptador con el `config` real e imprime los items y el cursor.
6. **Redeploy**: tras esto, redeployar a Vercel. La ruta de polling es genérica — el próximo tick de cron ya incluye Discord.

## Decisiones de diseño
- **Polling REST, no gateway**: traer mensajes con `GET /channels/{id}/messages?after=` es stateless y encaja con el cron; no hace falta un bot con conexión persistente.
- Misma interfaz `SourceAdapter` que el resto. Degradación elegante sin token.

## Criterio de éxito
- Con `DISCORD_BOT_TOKEN` válido y canales configurados, `npx tsx scripts/test-discord-adapter.ts` trae mensajes como `RawItem`s válidos y devuelve un cursor.
- Sin token, el adaptador devuelve `[]` y el pipeline sigue corriendo.
- Tras activar la fuente y redeployar, `POST /api/poll/discord` inserta leads de Discord deduplicados.
- `npm run build` pasa.
