# 34 — (Opcional) Fuente Workana

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger + Vercel.

Paso **34 de 35**, y es **opcional**.

**Ya existe:** el sistema completo en producción con 7 fuentes (pasos 00–33); `lib/sources/` con la interfaz `SourceAdapter` y adaptadores de referencia (04, 06–10); `lib/http.ts`, `lib/logger.ts` (02); `SCRAPER_API_KEY` opcional en env (01).

Workana es la bolsa freelance **más relevante para el mercado argentino/LatAm**, pero es la única fuente con un **costo y una fragilidad reales**. Hacé este paso solo si aceptás ese trade-off.

> **Aviso de costo y fragilidad.** Workana no tiene API pública y está protegida por Cloudflare con anti-bot moderno. Hay dos caminos, ambos con desventajas:
> - **(A) Servicio de scraping pago** (ScrapingBee, ScrapFly, Bright Data, etc.) — confiable, pero cuesta **~US$30–50/mes**. Es el camino recomendado si hacés Workana.
> - **(B) Navegador headless propio** (Playwright/Camoufox) — sin costo de servicio, pero **frágil en serverless**, pesado, y se rompe con cada actualización del anti-bot de Workana.
> Cualquiera de los dos requiere mantenimiento. El resto del sistema (7 fuentes) no tiene este problema.

## Tarea
1. **`lib/sources/workana.ts`** — implementar `SourceAdapter` con `slug = 'workana'`:
   - `configSchema`: Zod → `{ searchUrls: string[] }` (URLs de búsqueda de proyectos en Workana, ej. filtradas por categoría web/apps).
   - `fetchItems(config, cursor)`:
     - **Si `SCRAPER_API_KEY` no está seteado, devolver `{ items: [], cursor }` sin error** (la fuente queda inerte).
     - Camino A (recomendado): traer cada `searchUrl` a través del servicio de scraping pago (usando `SCRAPER_API_KEY` y `fetchWithRetry`), que devuelve el HTML ya resuelto.
     - Parsear el HTML de los listados de proyectos. El `cursor` guarda `{ lastSeenIds }` o la fecha del proyecto más nuevo visto.
     - Devolver `{ items, cursor }`.
   - Logueá con `lib/logger.ts`. Aislá los fallos: si Workana se rompe, no debe afectar a las otras fuentes.
2. **Migración para registrar la fuente**: insertar (vía MCP de Supabase) una fila en `sources` con slug `workana`, `enabled = false`, y un `config` con `searchUrls` de ejemplo.
3. **Registrar** el adaptador con `registerSource(...)` e importarlo desde `lib/sources/index.ts`.
4. **`scripts/test-workana.ts`** — script `npx tsx` que prueba el adaptador.
5. **Documentar en el README** (sección Workana, opcional): el costo, la fragilidad, cuál de los dos caminos se eligió, y que la fuente está deshabilitada por defecto.
6. **Redeploy** tras agregar el adaptador.

## Decisiones de diseño (respetalas)
- **Aislamiento estricto**: Workana es la fuente más propensa a romperse. Su adaptador debe capturar todos sus errores y nunca tumbar el poll de las otras fuentes.
- Arranca **deshabilitada**: se activa manualmente desde el panel solo cuando el scraping esté funcionando y el dueño acepte el costo.
- Degradación elegante: sin `SCRAPER_API_KEY`, devuelve `[]`.

## Criterio de éxito
- `lib/sources/workana.ts` existe, registrado, y sin `SCRAPER_API_KEY` devuelve `[]` sin romper nada.
- Con el scraping configurado, `npx tsx scripts/test-workana.ts` trae proyectos de Workana como `RawItem`s válidos.
- El README documenta claramente el costo y la fragilidad de esta fuente.
- `npm run build` pasa.
