# 04 — Interfaz de fuentes y registry

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger.

Paso **04 de 35**.

**Ya existe:** proyecto Next.js con la carpeta `lib/sources/`, infraestructura compartida (`lib/logger.ts`, etc.) (00–02), esquema Supabase con `sources` (columnas `config` y `cursor`) (03).

Este paso define el **patrón de adaptadores de fuente**, que permite agregar nuevas fuentes sin reescribir el resto del sistema. El plan implementa 8 fuentes (Hacker News, Reddit, Bluesky, Freelancer.com, RSS, Telegram, Discord, Workana) — todas sobre esta misma interfaz.

## Tarea
1. **`lib/sources/types.ts`** — definir y exportar:
   - `RawItem`: item crudo normalizado. Campos: `externalId: string | null`, `title: string`, `body: string`, `url: string`, `author: string | null`, `postedAt: string | null` (ISO 8601), `raw: unknown`.
   - `SourceCursor`: alias para un objeto JSON serializable (el high-water-mark de la fuente).
   - `FetchResult`: `{ items: RawItem[]; cursor: SourceCursor }`.
   - `SourceAdapter`: interfaz con:
     - `slug: string`
     - `displayName: string`
     - `configSchema: ZodType` — schema de Zod que valida el `config` de esa fuente
     - `fetchItems(config, cursor: SourceCursor): Promise<FetchResult>` — recibe el `config` ya validado y el cursor anterior; devuelve los items nuevos y el cursor actualizado.
2. **`lib/sources/registry.ts`** — un `Map<string, SourceAdapter>` interno y las funciones `registerSource(adapter)`, `getSource(slug)`, `listSources()`.
3. **`lib/sources/index.ts`** — re-exporta el registry. Más adelante importará los adaptadores para forzar su registro; por ahora solo re-exporta el registry.

## Decisiones de diseño (respetalas)
- **Patrón adaptador**: agregar una fuente nueva = crear un archivo que implemente `SourceAdapter` y registrarlo. Ningún otro código del sistema cambia.
- **Polling incremental por cursor**: la fuente recibe su cursor anterior y devuelve uno nuevo, así trae solo lo nuevo. El cursor lo persiste la ruta de polling (paso 12).
- **Config tipada**: cada adaptador valida su `config` con `configSchema`. Un `config` inválido se detecta temprano.

## Criterio de éxito
- `npm run build` pasa.
- El registry expone `registerSource`, `getSource` y `listSources`, y compila sin adaptadores registrados.
- La interfaz `SourceAdapter` incluye `configSchema` y `fetchItems` con cursor.
