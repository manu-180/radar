# 29 — Verificación end-to-end y runbook

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger + Vercel.

Paso **29 de 35**.

**Ya existe:** la aplicación completa deployada en Vercel, con las variables de entorno cargadas y los jobs de Supabase Cron apuntando a producción (pasos 00–28). Fuentes activas: Hacker News, Reddit, Bluesky, Freelancer.com, RSS.

Este paso **verifica que el sistema corre solo, de punta a punta**, y deja documentación.

## Tarea
1. **Verificación end-to-end** (disparando las rutas a mano con el header `x-cron-secret`):
   - `POST ${APP_URL}/api/cron/dispatch` → aparecen leads nuevos de varias fuentes.
   - `POST ${APP_URL}/api/process` → los leads `pending` quedan `done` y clasificados, con `llm_cost_usd` cargado.
   - `POST ${APP_URL}/api/notify` → llega un WhatsApp real al dueño por cada lead calificado.
   - Abrir el dashboard de producción, loguearse y revisar leads, el embudo de métricas y la configuración.
   - `GET ${APP_URL}/api/health` devuelve `status: ok`.
2. **Verificación de autonomía**: esperar al próximo tick de cron (~20 min) sin intervención y confirmar un `run` de poll exitoso nuevo en `runs`.
3. **Convertir el README en un runbook** con: arquitectura del sistema; lista de variables de entorno (requeridas y opcionales); las 8 fuentes y cómo agregar una nueva (implementar `SourceAdapter` con su `configSchema` + registrarla + fila en `sources`); cómo sumar feeds RSS sin código; cómo funciona el cron (Supabase Cron → rutas de Vercel; re-correr `cron.sql` tras cambiar la URL); cómo ajustar keywords y reglas desde el dashboard; cómo correr la evaluación del clasificador (`npm run eval`); costos (~US$10–15/mes de Claude API; resto en free tier); y troubleshooting (mirar `runs`, `/api/health` y los logs por `runId`).

## Criterio de éxito
- La verificación end-to-end pasa: dispatch → leads nuevos; process → clasificados con costo; notify → WhatsApp recibido.
- `GET /api/health` en producción devuelve `status: ok`.
- A los ~20 min, sin intervención, el cron dispara un ciclo solo.
- El README es un runbook completo y utilizable.
