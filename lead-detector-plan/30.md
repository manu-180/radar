# 30 — Fuente Telegram: setup

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger + Vercel.

Paso **30 de 35**.

**Ya existe:** el sistema completo en producción con 5 fuentes (pasos 00–29); `lib/env.ts` con las variables `TELEGRAM_*` opcionales (01); fila en `sources` con slug `telegram`, deshabilitada (03).

Telegram es una **fuente core** del plan (valiosa para leads en español/Latinoamérica). Requiere un **setup manual único** porque usa el cliente MTProto. Este paso prepara ese setup; el paso 31 implementa el adaptador.

## Por qué Telegram necesita setup
No tiene una API HTTP simple para leer canales públicos arbitrarios: usa el cliente MTProto (librería GramJS), que necesita una sesión autenticada generada una vez de forma interactiva.

## Tarea
1. **Dependencias**: `npm install telegram input`.
2. **`scripts/telegram-login.ts`** — script de login interactivo: usa `StringSession` de GramJS, pide teléfono y el código que llega por Telegram, y al final **imprime el `TELEGRAM_SESSION`**.
3. **Documentar el setup manual en el README** (sección Telegram):
   - Crear una app en `https://my.telegram.org` → obtener `api_id` y `api_hash`.
   - Correr una vez `npx tsx scripts/telegram-login.ts`, ingresar teléfono y código, copiar el `TELEGRAM_SESSION` impreso a `.env.local` y a Vercel (junto con `TELEGRAM_API_ID` y `TELEGRAM_API_HASH`).

## Decisiones de diseño
- El setup manual está aislado en este paso. El adaptador (paso 31) degrada con elegancia: sin las variables, la fuente devuelve `[]` y nada se rompe.

## Criterio de éxito
- `npm install` agrega `telegram` e `input` sin romper el build.
- `scripts/telegram-login.ts` existe y, con `api_id`/`api_hash` válidos, completa el login e imprime un session string.
- El README documenta el setup paso a paso.
- `npm run build` pasa.
