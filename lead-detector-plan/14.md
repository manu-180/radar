# 14 — Set de evaluación del clasificador

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger.

Paso **14 de 35**.

**Ya existe:** `lib/ai/classifier.ts` con `classifyLead` (13).

Este paso construye un **set de evaluación** del clasificador: ejemplos etiquetados que miden su precisión y detectan regresiones cuando se toca el prompt.

## Tarea
1. **`test/fixtures/classifier-cases.ts`** — un array de **20 a 30 casos** etiquetados. Cada caso: `{ title, body, source, lang, expectedCategory }`. Cubrir:
   - Casos `hiring` claros, en español y en inglés, de distintas fuentes (Reddit, HN, Bluesky, Freelancer, RSS).
   - Casos `noise`: gente buscando trabajo, ofertas de empleo full-time, discusión técnica, spam, reclutadores.
   - Casos `maybe`: pedidos ambiguos o con poco contexto.
   - Al menos 1 caso con un intento de prompt injection en el body.
2. **`scripts/eval-classifier.ts`** — script `npx tsx` que corre `classifyLead` sobre cada caso y reporta: precisión global, una matriz de confusión simple, y los casos fallados.
3. **Script de npm** `eval` → `tsx scripts/eval-classifier.ts`.

## Decisiones de diseño (respetalas)
- La evaluación **no va en `npm test` ni en el CI**: hace llamadas reales a la API de Claude (cuesta y requiere `ANTHROPIC_API_KEY`). Se corre a mano con `npm run eval` al modificar el prompt del clasificador.

## Criterio de éxito
- `npm run eval` corre y reporta precisión global + matriz de confusión.
- La precisión global es **≥ 85%**. Si es menor, ajustar el system prompt o los few-shot del paso 13.
- El caso con prompt injection se clasifica por su contenido real.
