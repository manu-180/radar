# 25 — Ruta de estado: /api/health

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger.

Paso **25 de 35**.

**Ya existe:** esquema con `runs`, `leads`, `notifications` (03); `lib/supabase/admin.ts`, `lib/security.ts` (01–02).

Este paso construye una **ruta de estado** que un monitor de uptime externo puede consultar.

## Tarea
1. **`app/api/health/route.ts`** (método `GET`; `dynamic = 'force-dynamic'`):
   - **Respuesta pública mínima** (sin secreto): solo `{ status: 'ok' | 'degraded' | 'down' }`. No expone counts ni detalles internos.
   - **Respuesta detallada**: si la request trae el secreto correcto (header `x-cron-secret` o query `?token=`, comparado timing-safe con `env.CRON_SECRET`), devolver además: último `run` exitoso por `kind` y hace cuánto; leads `pending` y antigüedad del más viejo; `runs` con `error` en 24 h; notificaciones `failed` recientes.
   - Derivar el `status` global: `down` si no hubo poll exitoso en mucho tiempo; `degraded` si hay errores o backlog; `ok` si todo sano.

## Decisiones de diseño
- **La salida pública es mínima a propósito**: un endpoint de health abierto no debe filtrar el estado interno.

## Criterio de éxito
- `GET /api/health` sin secreto devuelve solo `{ status }`.
- `GET /api/health` con el secreto devuelve el detalle completo.
- El `status` global es coherente con el estado real.
- `npm run build` pasa.
