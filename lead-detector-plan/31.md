# 31 — Fuente Telegram: adaptador

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger + Vercel.

Paso **31 de 35**.

**Ya existe:** `lib/sources/` con la interfaz `SourceAdapter` (con `configSchema` y `fetchItems` con cursor), el registry y los adaptadores HN/Reddit/Bluesky/Freelancer/RSS como referencia (04, 06–10); `lib/logger.ts` (02); las dependencias `telegram`/`input` y el script de login (30); fila en `sources` con slug `telegram` (03).

Este paso implementa el **adaptador de Telegram**.

## Tarea
1. **`lib/sources/telegram.ts`** — implementar `SourceAdapter` con `slug = 'telegram'`:
   - `configSchema`: Zod → `{ channels: string[] }`.
   - `fetchItems(config, cursor)`:
     - Si faltan las variables `TELEGRAM_*`, devolver `{ items: [], cursor }` sin error.
     - El `cursor` guarda `{ [channel]: lastMessageId }`.
     - Crear el cliente GramJS con `TELEGRAM_SESSION`, conectar, y por cada canal traer los mensajes posteriores a su `lastMessageId`. Desconectar al terminar. Timeout defensivo.
     - Mapear cada mensaje a `RawItem`: `externalId` = `<canal>:<messageId>`; `body` = texto; `title` = primera línea recortada; `url` = `https://t.me/<canal>/<messageId>`; `author` = el canal; `postedAt` = fecha del mensaje.
     - Devolver `{ items, cursor }` con el cursor actualizado por canal.
2. **Registrar** el adaptador con `registerSource(...)` e importarlo desde `lib/sources/index.ts`.
3. **Activar la fuente**: actualizar la fila `telegram` en `sources` → `enabled = true` y `config.channels` con canales públicos reales de freelance/proyectos en español.
4. **`scripts/test-telegram.ts`** — script `npx tsx` que ejecuta el adaptador con el `config` real e imprime los items y el cursor.
5. **Redeploy**: tras esto, redeployar a Vercel. La ruta de polling es genérica — el próximo tick de cron ya incluye Telegram.

## Decisiones de diseño
- Misma interfaz `SourceAdapter` que el resto: sumar Telegram no toca el pipeline, la clasificación, las notificaciones ni el dashboard.
- Degradación elegante: sin las variables configuradas, la fuente devuelve `[]`.

## Criterio de éxito
- Con las variables `TELEGRAM_*` configuradas, `npx tsx scripts/test-telegram.ts` trae mensajes como `RawItem`s válidos y devuelve un cursor.
- Sin esas variables, el adaptador devuelve `[]` y el pipeline sigue corriendo.
- Tras activar la fuente y redeployar, `POST /api/poll/telegram` inserta leads de Telegram deduplicados.
- `npm run build` pasa.
