# 11 — Helpers de base de datos: runs y persistencia de leads

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger.

Paso **11 de 35**.

**Ya existe:** `lib/supabase/admin.ts` con `getAdminClient()` (01); `lib/logger.ts` (02); esquema Supabase con `leads` y `runs` (03); `lib/sources/types.ts` con `RawItem` (04).

Este paso construye los **helpers de base de datos**: registro de corridas y persistencia deduplicada de leads.

## Tarea
1. **`lib/db/runs.ts`** (con `import 'server-only'`):
   - `startRun(kind, source?)` — inserta una fila en `runs` con `status='running'` y devuelve su `id`.
   - `finishRun(id, { status, itemsFound?, itemsNew?, itemsProcessed?, error? })` — actualiza la fila: `status`, contadores, `finished_at = now()`.
2. **`lib/db/leads.ts`** (con `import 'server-only'`):
   - `persistLeads(rows): Promise<{ found: number; new: number }>` — recibe filas de lead ya armadas (con `source`, `external_id`, `content_hash`, `title`, `body`, `url`, `author`, `lang`, `posted_at`, `raw`, `prefilter_matched`, `llm_status`, `notify_status`) y las guarda deduplicadas:
     1. Juntar todos los `content_hash` y `(source, external_id)` del lote.
     2. Consultar en `leads` cuáles ya existen (por `content_hash` o por `(source, external_id)`).
     3. **Items ya vistos**: `update` solo de `last_seen_at = now()`.
     4. **Items nuevos**: `insert` usando **`ON CONFLICT DO NOTHING` sin especificar columna de conflicto** — así cubre las dos restricciones únicas sin tirar excepción.
     5. Devolver `found` = total del lote y `new` = filas realmente insertadas.
   - Los leads que no pasaron el pre-filtro entran con `llm_status='skipped'` y `notify_status='skipped'`.

## Decisiones de diseño (respetalas)
- **La deduplicación la garantiza la base** (índices únicos del paso 03).
- **`ON CONFLICT DO NOTHING` sin target es deliberado**: con dos índices únicos, nombrar uno solo haría que un choque por el otro lance excepción.
- `persistLeads` recibe filas ya normalizadas y filtradas: no hace fetch ni clasifica.

## Criterio de éxito
- `npm run build` pasa.
- **Test** `test/leads-dedup.test.ts`: insertar un set de filas devuelve `new` = N; reinsertar el mismo set devuelve `new: 0` y no duplica.
- `startRun`/`finishRun` crean y cierran filas en `runs` correctamente.
