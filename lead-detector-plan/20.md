# 20 — Lista de leads

## Contexto
**Lead Detector** monitorea plataformas online buscando gente que busca contratar un developer, filtra los posts con IA (Claude) y avisa por WhatsApp. Stack: Next.js (App Router) + Supabase + Claude API + Wassenger.

Paso **20 de 35**.

**Ya existe:** dashboard con login y layout con navegación (19); esquema con la tabla `leads` (03); `lib/supabase/admin.ts` con `getAdminClient()` (01).

Este paso construye la **pantalla principal del dashboard**: la lista de leads para triagear.

## Tarea
1. **`app/(dashboard)/leads/page.tsx`** — Server Component que lee con `getAdminClient()`:
   - Tabla con columnas: fuente, título (recortado), score, categoría, fecha del post, estado de notificación y feedback.
   - Categoría con color: `hiring` verde, `maybe` ámbar, `noise` gris.
   - **Filtros** por query params: fuente, categoría, `llm_status`, feedback, y buscador por texto en el título.
   - Orden por `first_seen_at` descendente. Paginar de a 50.
   - Por defecto mostrar lo relevante primero (categoría `hiring`/`maybe`, sin feedback).
   - Cada fila enlaza al detalle `/leads/[id]` (paso 21).

## Decisiones de diseño
- Todo se renderiza en el server con el cliente admin de Supabase.
- Con 8 fuentes posibles, el filtro por fuente es importante: dejalo prolijo.

## Criterio de éxito
- `/leads` lista los leads reales de la base.
- Los filtros por fuente, categoría, estado y el buscador funcionan vía query params.
- La paginación funciona con más de 50 leads.
- `npm run build` pasa.
